# DBMON - Database Monitoring

End-to-end monitoring of SQL, NoSQL, cache, and messaging database platforms.

> **Recommended:** For the best experience, import the notebooks into your Dynatrace tenant. Each one is available as a Dynatrace notebook (JSON) file, and its DQL queries run against your own environment's data.

## Structure
- notebooks/ — Dynatrace notebook JSON files
- pdfs/ — Printable versions of each notebook
- markdown/ — Markdown exports of the notebooks

## Notebook Lineup
1. [Database Monitoring Fundamentals](markdown/-[DBMON]-01-database-monitoring-fundamentals.md) — How Dynatrace monitors databases, span anatomy, and how database calls attach to services
2. [SQL Database Monitoring](markdown/-[DBMON]-02-sql-databases.md) — Monitoring SQL Server, PostgreSQL, Oracle, MySQL, and other relational databases
3. [NoSQL Database Monitoring](markdown/-[DBMON]-03-nosql-databases.md) — Monitoring MongoDB, DynamoDB, Cassandra, Cosmos DB, and other NoSQL platforms
4. [Cache and Messaging Monitoring](markdown/-[DBMON]-04-cache-and-messaging.md) — Monitoring Redis, Memcached, RabbitMQ, Kafka, and message brokers
5. [Query Analysis](markdown/-[DBMON]-05-query-analysis.md) — Performance analysis, slow query identification, and optimization techniques
6. [Dashboards and Alerting](markdown/-[DBMON]-06-dashboards-and-alerting.md) — Database performance dashboards and alert strategies
99. [Best Practice Summary](markdown/-[DBMON]-99-best-practice-summary.md) — Consolidated best practices from the DBMON series

## Usage
1. Open a notebook from the lineup below. Each one is also available as a Dynatrace notebook (JSON) to import into your tenant, so its queries run against your own data, and as a PDF for print.
2. Start with Database Monitoring Fundamentals to understand the monitoring architecture.
3. Explore database-specific notebooks for your technology stack (SQL, NoSQL, cache, messaging).
4. Master query analysis and create dashboards for proactive database performance management.
